# ConnectAbroad SEO

Paths below are relative to the project root. Read `docs/SEO-AUDIT.md`. This is an authorized fresh React/Vite/TypeScript application with ₹0 additional spend. Create missing frontend routes when requested; inspect actual output as it becomes available. A plan audit is not a live crawl or ranking result; no paid SEO tool or domain is required.

## Scope the audit honestly

Record available code, URL, crawl, analytics and Search Console evidence. Mark absent evidence not checked. Use current Google Search Central primary guidance for unstable factual claims. Never invent scores, search volumes, indexing status or revenue forecasts.

## Apply the launch contract

- Public marketing pages, maintained editorial guides and curated useful hubs are the only eligible search inventory. Member discovery/profiles, chats, notifications, reports, admin and private media stay authenticated at beta launch.
- Authentication and authorization protect privacy. Robots controls and noindex do not secure content. Utility-page noindex must be readable to the crawler; never open private data merely so a crawler can see it.
- Use React Router Framework Mode on Vite, `ssr: false` and an explicit approved public-page prerender list for build-time HTML without a production Node rendering server. Verify headings/metadata/links in generated HTML, canonicals/sitemap, known private-route fallback and real 404 handling. No fixture PII may enter public build output.
- No automatic city/college/language permutations, fabricated community density, member data harvesting, ratings or professional-outcome claims.
- Draft guides from original consented experience plus appropriate official sources. Assign a real accountable editor, source date and maintenance trigger. Review consequential advice before publication.
- Use structured data only when it matches visible supported content. Recheck current feature support; do not promise FAQ rich results. Label member links `ugc`, commercial placements `sponsored`, and disclose sponsorship visibly.

## Verify and report

Check anonymous/private response behavior and caching, initial HTML, metadata/canonicals, sitemap, redirects, removed pages, staging controls, mobile usability and performance. Report lab conditions separately from field Core Web Vitals.

Return prioritized findings as evidence → change → owner → acceptance proof → status (applied to plan, implemented, or verified live). Fix authorized issues within scope, then rerun relevant checks. Do not mark production corrections complete from a specification alone. Measure qualified organic signup/activation over time; first-100 acquisition still depends on the community plan.
